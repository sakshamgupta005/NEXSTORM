### Key Observations
1. **Timestamp Format:** Open-Meteo timestamps are formatted as `YYYY-MM-DDTHH:mm` in the requested timezone (`Asia/Kolkata`, `utc_offset_seconds: 19800`). Normalized explicitly to ISO with offset `+05:30` (`YYYY-MM-DDTHH:mm:00+05:30`).
2. **Ensemble Member Schema:** ECMWF IFS provides 51 precipitation columns: `precipitation` (control/deterministic run) and `precipitation_member01` through `precipitation_member50`.
3. **SACHET RSS Format:** Feed uses standard RSS 2.0 `<item>` with `<guid>`, `<title>`, `<description>`, `<category>`, `<link>`, `<author>`, and `<pubDate>`. Punjab filtering checks `<author>` and text bodies against Punjab SDMA, IMD Chandigarh, and 23 official Punjab districts.

## 4. Resilience, Caching, and Fallback Behavior

1. **API Client Resilience:** Configured via `createApiClient`:
   - 8-second request timeout (`timeoutMs: 8000`).
   - 2 retries with exponential backoff and jitter (`retries: 2, retryDelayMs: 500`).
   - Automatic retry for HTTP 429 and 5xx; non-idempotent methods protected.
2. **In-Memory Cache (`ICache`):**
   - Active forecast TTL: 1,800 seconds (30 minutes) via `FORECAST_TTL_SECONDS`.
   - In-flight and subsequent requests within TTL served from memory with `provenance.kind = 'cached'`.
3. **Snapshot Fallback (`snapshots.ts`):**
   - Valid upstream fetches persisted to `public/data/snapshots/{cityId}-rainfall.json`.
   - On upstream failure, snapshot loaded if age $\le 21,600$ seconds (6 hours) via `FORECAST_STALE_MAX_SECONDS`.
   - Age accurately reported in `provenance.ageSeconds` with `provenance.kind = 'cached'`.
   - If snapshot exceeds staleness or is missing, endpoint returns status `degraded` without fake numbers.

## 7. Known Limitations & Recommendations for P3

- **Ensemble API Rate Limits:** Open-Meteo free tier permits 10,000 daily calls and up to 600 calls/hour. Multi-member queries should always utilize cache and snapshots.
- **SACHET RSS Geographic Granularity:** NDMA SACHET RSS items primarily specify district or state-level coverage in textual fields (`author`, `title`). Sub-district / ward-level geolocation requires CAP XML dereferencing via the alert `link`, planned for P3/P4.
- **P3 Recommendation:** Implement historical replay mode (`GET /api/risk?mode=replay`), connecting historical archive adapters and evaluation metrics.
