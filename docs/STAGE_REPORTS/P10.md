## 1. Executive Summary

Stage P10 builds the foundational **Ground-Truth Evidence Layer** for NEXSTORM in Amritsar, Punjab. It directly satisfies the objective of creating an auditable, extensible observation system supporting NEXSTORM's three core pillars:
1. Area-level susceptibility and rainfall-triggered risk.
2. Building-level exposure assessment.
3. Road-segment risk assessment and flood-aware route planning.

Crucially, P10 enforces the **Non-Conflation Directive**:
- Distinguishes **what was reported** by citizens from **what was corroborated** by independent nearby reports, **what was independently verified** by municipal authorities, and **what is modeled** by hyetographs and terrain matrices.
- Eliminates fabricated sample data: seeds only the 15 documented historical news incidents from The Tribune India as baseline verified records.
- Protects citizen privacy: zero PII storage using salted SHA-256 pseudonymous reporter hashing, with automatic redaction from all public API outputs.
- Prevents coordinated abuse: sliding-window rate limiting (5 / 10m per IP) and proximity deduplication (50m, 15m).
- Integrates an interactive reporting modal and live observations map layer into the Amritsar console without redesigning existing workflows.

## 2. File Change Ledger

### Created Modules & Components
- `src/lib/observations/types.ts`: Canonical observation schema, lifecycle state types (`submitted`, `under_review`, `corroborated`, `verified`, `rejected`, `expired`), verification records, spatial match contracts, and freshness indicators.
- `src/lib/validations/observation.ts`: Rigorous Zod validation schemas enforcing Amritsar bounding box limits ($31.50 \le \text{lat} \le 31.80$, $74.70 \le \text{lng} \le 75.05$), past timestamps ($\le \text{now}$, $\ge \text{now} - 7\text{ days}$), text length limits, and safe URL schemes.
- `src/lib/observations/service.ts`: Core `ObservationService` singleton featuring:
  - Salted SHA-256 pseudonymous reporter hash generator.
  - Spatial matching to 250m analysis grid (`matchPointToGrid`) and road network centerline projection (`matchObservationToRoadSegment` with 30m snapping tolerance).
  - Anti-duplicate proximity engine (50m, 15 minutes).
  - Corroboration clustering (150m, 3 hours, distinct reporter origins).
  - Lifecycle state machine and authorized verification moderation.
  - Atomic file persistence (`observations.json.tmp` $\to$ `observations.json`).
  - Automatic baseline seeding of 15 historical Tribune records.
- `src/app/api/observations/route.ts`:
  - `GET /api/observations`: Query observations with filtering by status, category, severity, cell ID, road ID, and freshness.
  - `POST /api/observations`: Submit community observation with IP rate-limiting, Zod schema validation, spatial snapping, and public reporter hash redaction.
- `src/app/api/observations/[id]/verify/route.ts`:
  - `PATCH /api/observations/[id]/verify`: Authorized moderation endpoint requiring Bearer reviewer token, enforcing immutable audit trail (`verifiedBy`, `verifiedAt`, `verificationMethod`, `verificationNotes`).
- `src/components/observations/ObservationReportModal.tsx`: Accessible dialog form for citizen reporting with interactive coordinate entry, device geolocation lookup, category/severity descriptors, and submission confirmation.
- `src/components/observations/ObservationsPanel.tsx`: Filterable observations evidence panel with status pills, corroboration counters, spatial cell/road links, and reviewer moderation tools.

## 4. Remaining External Infrastructure Requirements

In accordance with non-negotiable hackathon starter principles, local fallback mechanisms were prioritized over pretending unconfigured cloud services exist. When transitioning to regional production deployment, the following external infrastructure should be provisioned:

1. **Persistent Database**:
   - PostgreSQL 15+ with PostGIS extension or Supabase Database (schema provided in `docs/OBSERVATION_DATA_MODEL.md`).
2. **Object Storage**:
   - S3-compatible bucket or Supabase Storage with pre-signed upload URLs and server-side EXIF metadata stripping.
3. **SMS / WhatsApp Gateway**:
   - Municipal broadcast integration for citizen alerts (NDMA SACHET / MCA WhatsApp bot).
