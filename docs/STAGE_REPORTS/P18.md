## 1. Executive Summary

NEXSTORM Stage P18 made the rainfall-driven hazard and risk scoring engine empirically testable against 15 years (2010–2024) of genuine ECMWF ERA5-Land hourly reanalysis data and 15 documented historical Tribune waterlogging incidents.

### Key Achievements
1. **Audited Complete End-to-End Rainfall Pipeline**:
   - Identified and resolved the UTC vs. IST timezone shift where evening UTC hours mapped to incorrect local calendar dates.
   - Identified cold-start accumulation truncation for early series hours and implemented `rollingSumWithAntecedent` to support proper 72-hour spinup windows.
   - Replaced silent imputation of missing values with explicit `dataQuality` tracking (`nullCount`, `completenessRatio`, `missingIndices`, `policy`).
2. **Integrated Genuine Historical Weather Evidence**:
   - Verified local 2010–2024 ERA5 hourly precipitation archive (`pipeline/cache/open_meteo_archive_jjas.json`, 125,664 hours, zero missing records).
   - Delivered `loadAmritsarHistoricalArchive` in `src/lib/weather/historical.ts` for offline, repeatable reanalysis extraction.
   - Added rigorous input validation and error handling for external historical forecast and archive query APIs.
3. **Built Reproducible Historical Backtesting Engine**:
   - Built `src/lib/evaluation/backtest.ts` executing chronologically hour-by-hour (ensuring $h \le t$, strictly zero future data leakage).
   - Built HTTP API endpoint `GET /api/evaluation/backtest` supporting dynamic seasonal queries (`?season=2023`, `?season=2024`, `?season=all`).
   - Delivered Python backtesting evaluation script `pipeline/scripts/14_run_backtest.py` exporting `public/data/evaluation/e4_backtest.json`.
4. **Empirical Evaluation Results**:
   - **Model Detection Skill**: Detected **8 of 9 reported event dates (88.9% POD, Wilson 95% CI: [56.5%, 98.0%])** across the 2023–2024 monsoons when accounting for the 24-hour publication lag / antecedent downpour window.
   - **IMD 64.5 mm Baseline**: Detected only **1 of 9 reported event dates (11.1% POD, Wilson 95% CI: [2.0%, 43.5%])**, demonstrating that urban waterlogging in Amritsar is triggered by sub-daily high-intensity rainfall ($P_{1h}, P_{3h}$) or saturated soil ($P_{72h}$) long before daily precipitation crosses the 64.5 mm threshold.
5. **Regression Verification**:
   - Built `tests/unit/p18-rainfall-validation-backtest.test.ts` (15 tests passing).
   - All **96 test suites and 926 tests pass with 0 failures** across the repository.
   - TypeScript `tsc --noEmit` and ESLint pass cleanly with 0 errors.

## 2. Phase 1 — Implementation Audit Findings

| Pipeline Stage | Finding / Defect | Remediation Implemented |
| :--- | :--- | :--- |
| **Weather Ingestion** | Missing interval replacement in `normalizeOpenMeteoResponse` lacked traceability. | Added `dataQuality` object (`nullCount`, `completenessRatio`, `missingIndices`, `policy`). If `nullCount > 0`, flagged as degraded. |
| **Timezone Alignment** | Raw UTC timestamps (`Z` suffix) were left unshifted, causing a 5.5 hour discrepancy where evening rainstorms mapped to the preceding calendar day. | Implemented `toIstTimestamp` and `toAmritsarDateString` to strictly align evaluations with Amritsar local calendar time (+05:30). |
| **Accumulation Windows** | `rollingSum` on cold start began summing at index 0, severely underestimating $P_{24h}$ and $P_{72h}$ for early series hours. | Created `rollingSumWithAntecedent` supporting pre-evaluation warmup windows. |
| **Chronological Purity** | Risk timeline evaluation risked future-data leakage if not strictly partitioned. | Built chronological backtesting harness ensuring hour $t$ evaluates strictly on data where $h \le t$. |
| **Publication Lag** | Tribune news articles published on date $D$ frequently reported inundation caused by downpours on date $D-1$. | Structured evaluation window to evaluate antecedent 24h precipitation leading into published article dates. |

## 6. Scientific Guardrails & Honest Disclaimers

1. **Non-Claims**:
   - NEXSTORM computes relative waterlogging susceptibility and rainfall hazard. It does **not** predict flood depth in centimeters.
   - Modeled alerts represent physical pooling hazard, not confirmed interior submergence.
2. **Incomplete Negative Space (Unlabelled Problem)**:
   - Unreported dates and locations cannot be classified as confirmed negative non-flooding zones. False Alarm Rate (FAR) cannot be computed defensibly without complete negative ground-truth logs across all 1,998 cells.
3. **Coarse Resolution Limit**:
   - The 11 km ERA5 reanalysis grid smooths localized convective cloudbursts; hyper-local microbursts require municipal automatic rain gauge (ARG) telemetry.
4. **Publication Lag**:
   - Journalistic accounts are published 12–24 hours post-storm. Evaluation must consider antecedent 24-hour rainfall windows.
