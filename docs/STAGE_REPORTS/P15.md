## 2. End-to-End Workflows Tested

All critical user workflows were validated end-to-end:

### Workflow A: Area-Level Assessment & Explanation
1. User loads `/city/amritsar` into the browser.
2. The interactive Leaflet map renders the 1,998-cell susceptibility grid colored by risk category (`low`, `moderate`, `high`).
3. Switching between **Live Mode**, **72h Replay Mode**, and **Scenario Simulator** recalculates risk in under 40ms without page reloads.
4. Clicking any grid cell queries `GET /api/cell/[cellId]` and opens the `CellDetailPanel`, showing exact factor contributions, depression depth, built-up fraction, and nearest historical waterlogging hotspot.
5. Upstream weather outage simulation falls back cleanly to the cached snapshot (`amritsar-rainfall.json`) with `kind: "cached"` rather than failing or injecting zero-risk hallucinated data.

### Workflow B: Building Footprint Catchment Exploration
1. In `/city/amritsar`, user toggles on the **"Buildings"** layer in the map controls.
2. Building polygons around historical hotspots and the GNDU campus load on-demand.
3. Clicking an individual footprint displays its verified metric footprint area ($m^2$), parent cell IDs, and catchment susceptibility tier (`Low`, `Moderate`, `High`).
4. The panel explicitly clarifies that the metric represents terrain catchment exposure, not structural flood damage.

### Workflow C: Flood-Aware Origin-to-Destination Route Planning
1. User toggles the **"Roads"** layer and selects route planning.
2. User selects an origin (e.g., Mall Road / Novelty Chowk: `[31.642, 74.875]`) and destination across an underpass corridor (e.g., SSSS Chowk Underpass: `[31.650, 74.868]`).
3. The routing engine executes sub-2ms A* pathfinding over 37,924 topological edges and returns 3 candidate routes:
   - **Candidate 1 (Shortest)**: The direct geometric path, traversing the flagged underpass corridor.
   - **Candidate 2 (Lower Modeled Exposure)**: Automatically detours around the underpass and elevated-risk cells via higher-elevation arterial segments.
   - **Candidate 3 (Balanced)**: Trade-off minimizing travel time while avoiding high-risk corridors.
4. Route comparison cards show distance, baseline travel time, high-risk distance, and unknown-coverage fractions.

### Workflow D: Citizen Observation Reporting & Moderation
1. User submits a waterlogging report with location coordinates and water depth category (`ankle_deep`, `knee_deep`, `waist_deep`).
2. Client and server validate coordinates within Amritsar bounds and snap to the nearest cell and road segment.
3. Reporter IP and user agent are salt-hashed using a server secret; the public API never exposes raw IP or hash values.
4. Moderation review (`PATCH /api/observations/[id]/verify`) verifies the report using the server `OBSERVATION_MODERATOR_KEY`, immediately promoting the snapped road segment's dynamic risk score to `high`.

## 3. Critical Defects Found & Fixes Made

1. **Defect (Performance/Network)**: `hotspot_buildings.geojson` (8.87 MB) was being fetched unconditionally on initial page render, even though the building layer defaulted to `showBuildings === false`.  
   **Fix**: Modified `src/app/city/[cityId]/page.tsx` to lazy-load building GeoJSON strictly when `showBuildings` is toggled on.
2. **Defect (Security/Authorization)**: Observation verification permitted fallback development reviewer tokens in production environments.  
   **Fix**: Hardened `src/app/api/observations/[id]/verify/route.ts` to strictly enforce `OBSERVATION_MODERATOR_KEY` in production (`NODE_ENV === 'production'`) and documented the variable in `.env.example`.
3. **Defect (Test Assertion/Disclaimer)**: Extended disclaimer string in `src/lib/provenance.ts` diverged from the canonical string asserted in golden historical replay tests.  
   **Fix**: Preserved the exact canonical string for `PERMANENT_DISCLAIMER` and encapsulated extended guidance under `EXTENDED_LIMITATION_DISCLAIMER`.
4. **Defect (Lint Hygiene)**: Lint configuration processed untracked reference files in `scratch/`.  
   **Fix**: Added `scratch/**` to `globalIgnores` in `eslint.config.mjs`, ensuring zero lint warnings across the active codebase.

## 6. Remaining Data, Infrastructure & Deployment Limitations

Honest scientific presentation requires highlighting the following structural limitations:

1. **Hydraulic Limitations**: Susceptibility models terrain depression depth and built-up land cover; it does not model underground storm drainage networks or predict water depth in centimeters.
2. **Road Network Simplifications**: Road segments in `routing_graph.json` are bidirectional due to OSM source data limitations; legal one-way streets and complex turn restrictions are unmodeled.
3. **Travel Velocity Baseline**: Route travel times use an uncalibrated 30 km/h baseline velocity without live vehicular congestion data.
4. **Building Exposure Bounds**: Footprint exposure quantifies macro-catchment intersection ($m^2$); it does not assess plinth height, interior inundation, or structural vulnerability.
5. **Observation Persistence**: Citizen observations persist to a local JSON file (`observations.json`); horizontal multi-instance scaling in production would require migrating this layer to PostgreSQL/Supabase.
